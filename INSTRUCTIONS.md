# INSTRUCTIONS.md — Port Times Tables to a web app

## Goal

Turn `reference/times-tables.html` into a hosted web app. A parent signs in, sets up a profile for each child, and the kids play on any device. Every answer is recorded per child. A parent dashboard shows which facts each child knows, which they're slow on, and which they're missing.

The game itself does not change. It's a port: same rules, same art, same feel. What's new is accounts, child profiles, saved progress per child, and the dashboard.

## Before you start (the parent does these by hand)

Claude Code can't create these accounts. Do them first and put the keys in `.env.local`:

1. **GitHub:** create an empty repo for this project.
2. **Supabase** (supabase.com, free tier is fine): create a project. Copy the Project URL and the `anon` public key. The service-role key is only needed for running migrations locally, never in the browser.
3. **Vercel** (vercel.com, free tier is fine): sign in with GitHub. You'll connect the repo in Phase 5.

## Stack

| Piece | Choice | Why |
|---|---|---|
| Front end | Vite + React + TypeScript | Plain single-page app, no server code needed |
| Backend | Supabase: Postgres, Auth, Row Level Security | Database, parent sign-in and per-family data isolation in one place; the browser talks to it directly |
| Hosting | Vercel | Deploys straight from GitHub |
| Tests | Vitest for game logic; Playwright for end-to-end | Playwright can drive the real game the way the parity check needs |

If you think a different choice is clearly better, say so at the Phase 0 checkpoint before building. Don't switch silently.

## What the game does today (port all of this)

Read `reference/times-tables.html` end to end. The list below summarizes it. Where it and the file differ, the file wins.

### Practice mode
- Random problems `a × b`. Both `a` and `b` are random from 2–12, always. **No ×1 problems anywhere.** A random pick won't repeat the previous problem. A review-pile pick can, which is a known quirk: keep it unless the parent says otherwise.
- Big on-screen number pad (1–9, ⌫, 0, ✓). A physical keyboard also works: digits, Backspace, Enter.
- **Right answer:** the answer turns green, the background animal flies into the backpack, the score and streak go up, and the next problem appears after a short delay. A new species shows "Fox jumped in your backpack!". Taps during that delay are ignored (no double-counting).
- **Wrong answer:** the correction card shows the full fact (`7 × 8 = 56`), then a "Got it" button. Nothing is taken away for a miss. That's deliberate.
- **Review pile:** a missed fact owes 2 more correct answers. Once at least 3 problems have passed since the last review, each new problem has a 55% chance of being a fact from the pile. Each correct answer on a pile fact pays off one.
- **No tables picker.** It was deliberately removed so a child can't stick to the easy tables. Don't add a way to narrow the tables, for the child or in parent settings, unless the parent asks.

### Animals and the backpack
- 13 regular animals: Cat, Dog, Bear, Bunny, Fox, Owl, Frog, Penguin, Whale, Turtle, Elephant, Pig, Panda. In practice they come from a shuffled bag: all 13 appear before the bag reshuffles.
- 5 rare animals: Axolotl, Salamander, Chameleon, Lizard, Snake. In practice mode only, each problem has a 5% chance (`RARE_CHANCE = 0.05`) of showing a rare one instead, split evenly across the 5. A rare one glows, shows "★ rare animal" above the problem, and shows "You caught the axolotl!" when caught.
- **Quest animals:** element versions of the regular animals. The art is generated by `recolor()` plus `DECOR` overlays in the reference file. Keep that approach; don't hand-draw new art. 8 groups × 8 animals = 64. Element groups can include rare animals (e.g. Ruby Chameleon).
- Backpack button (top right) shows `found / total`. Opening it shows sections: Animals, Rare, Water, Earth, Fire, Ice, Emerald, Ruby, Golden, Diamond. Uncaught slots show "?" and repeats show ×N.
- Total collectibles: 82 (13 regular + 5 rare + 64 quest).

### Quests
| id | Name | Problems in a row | Reward |
|---|---|---|---|
| mystery | Mystery Box | 1 | Random animal from all 64 quest animals (no preference for new ones). **Once per calendar day**, used up only when won. A wrong answer shows "Not quite. The answer is: …" with Try again / Stop |
| pick | Pick-a-Pet Quest | 8 | Child chooses any of the 13 regular animals, or 1 of the 5 rare animals (max one rare per calendar day) |
| water | Water Quest | 10 | Water: Whale, Frog, Turtle, Penguin, Axolotl, Salamander, Snake, Dog |
| earth | Earth Quest | 12 | Earth: Bunny, Elephant, Pig, Bear, Dog, Lizard, Fox, Panda |
| fire | Fire Quest | 14 | Fire: Fox, Dog, Cat, Bear, Owl, Lizard, Snake, Pig |
| ice | Ice Quest | 18 | Ice: Penguin, Bunny, Bear, Owl, Whale, Fox, Cat, Elephant |
| emerald | Emerald Quest | 19 | Emerald: Frog, Turtle, Salamander, Cat, Panda, Chameleon, Snake, Owl |
| ruby | Ruby Quest | 21 | Ruby: Axolotl, Fox, Pig, Bunny, Dog, Chameleon, Lizard, Bear |
| golden | Golden Quest | 23 | Golden: Bear, Elephant, Penguin, Cat, Owl, Dog, Panda, Snake |
| diamond | Diamond Quest | 25 | Diamond: Panda, Owl, Elephant, Whale, Fox, Axolotl, Bunny, Chameleon |

- **Difficulty is the length only.** Every quest uses the same problem generator as practice, including the review pile. Diamond must stay the longest.
- During a quest: there's a progress track with one segment per problem, the quest's symbol replaces the background animal, and nothing goes into the backpack per problem. The Quests button is hidden.
- One wrong answer ends the quest. The miss segment turns coral, the correction card says "Quest over. The answer is: …", and the buttons are "Try again" and "Stop".
- **Win:** reward screen. For Pick-a-Pet, a grid of the 13 regular and 5 rare animals (rare ones with a gold border). **Only one rare pick per calendar day:** once one is taken, the rare buttons are disabled and labeled "tomorrow" until the next local day. Each animal is marked "new!" or "have ×N". For element quests, a random animal of that type, **chosen from ones the child doesn't have yet when possible**, then a "Put it in my backpack" button. The animal flies into the backpack.
- When a panel (Quests or Backpack) is open, it takes over the screen and keyboard answering is paused.

### Look and feel
- Keep the palette, the Fredoka font, layout, animations, wording and SVG art exactly as in the reference file. Respect `prefers-reduced-motion` as the file does.
- Phone-first; must also work on tablet and laptop.

## What's new

### Accounts and profiles
- **Parent account:** Supabase Auth with email and password (magic link is fine too). Only parents have accounts. Children never enter an email.
- **Child profiles:** created by the parent. Each has a display name, an avatar picked from the regular animals, and an optional 4-digit PIN. Store a hash of the PIN, never the PIN itself.
- **Kid mode:** on a device where the parent is signed in, the app opens to "Who's playing?". The child taps their profile, enters their PIN if one is set, and plays.
- **Parent gate:** the dashboard and settings require the parent's password again, or a separate parent PIN, so a child on the same device can't open them. Switching child profiles goes back through "Who's playing?".

### What to record
Log every answer. Everything else in the dashboard is computed from this log.

- `attempts`: `child_id, a, b, given_answer, correct (bool), response_ms, mode ('practice' | 'quest'), quest_run_id (nullable), was_review (bool), created_at`
  - `response_ms` runs from when the problem is shown to when ✓ or Enter is pressed. Pause the timer while the tab is hidden or a panel is open, and cap it at 60,000 ms.
- `quest_runs`: `child_id, quest_id, length, reached (problems answered right), result ('won' | 'failed' | 'quit'), reward_id (nullable), started_at, ended_at`
- `catches`: `child_id, collectible_id, source ('practice' | 'quest' | 'pick' | 'mystery'), created_at`. **Enforce the once-a-day rules (Mystery Box, rare pick) on the server** (a `mystery` catch, or a rare `pick` catch, already exists for this child today in the family's time zone → reject), not just in the UI, since browser state is easy to reset. Backpack counts come from this table (a view or query is fine).
- `game_state`: one row per child: review pile (`{"7x8": 2, ...}`), recent rare-animal state if needed.
- `children`: `id, parent_id, name, avatar, pin_hash (nullable), created_at`

Use stable string IDs for collectibles (`cat`, `fire-fox`, `golden-penguin`, …), not display names.

**RLS:** a parent can read and write only rows whose `child_id` belongs to a child with `parent_id = auth.uid()`. Write a test that proves parent A can't read parent B's children, attempts or catches.

### Parent dashboard
Per child, with a child switcher:

1. **Fact grid (the main view):** an 11 × 11 grid, a = 2–12 down the side and b = 2–12 across the top. Each cell is colored by status over that fact's last 5 attempts:
   - **Fluent:** at least 4 of the last 5 correct, with a median time under the fluency threshold (default 3 s, adjustable in settings).
   - **Correct but slow:** mostly correct, but over the threshold. He's probably working it out, not remembering it.
   - **Shaky:** less than 80% correct.
   - **Not seen yet.**

   Toggle between status, accuracy % and median time. Tapping a cell shows that fact's attempt history. Keep 7×8 and 8×7 as separate cells, plus an option to merge commuted pairs.
2. **Trend:** problems answered per day, accuracy per day and median response time per day for the last 30 days. Count a "session" as a run of answers with no gap over 10 minutes, and show minutes practiced per day.
3. **Needs work:** the 10 weakest facts (slowest and least accurate), plus what's currently in the review pile.
4. **Quests:** attempts and wins per quest, the farthest he's gotten in each, and the longest run of correct answers in a row.
5. **Backpack:** found / 82, and which quest groups are still incomplete.
6. **Settings:** fluency threshold, PIN reset, rename or delete child (with confirmation). Deleting a child deletes all their data.

Make the dashboard readable on a phone too. Don't show children's data to anyone except their parent.

## Build phases

### Phase 0 — Read and plan
- Read `reference/times-tables.html` completely. Write `docs/behavior-inventory.md`: every rule, number, message string, animation and edge case you find. Note anything the summary above leaves out or gets wrong.
- Propose the folder structure, how the game logic will be split into modules, and the Supabase schema as SQL.
- ✅ **Checkpoint 0:** show the inventory, structure and schema. Wait for approval.

### Phase 1 — Port the game, no backend yet
- Scaffold Vite + React + TS. Port the game with state kept in memory or localStorage for now.
- Pure game-logic modules with Vitest tests for at least:
  - No ×1 problems over 10,000 generated; every table 2–12 appears as both first and second factor; no immediate repeats from random picks.
  - Review pile: a miss adds 2; correct answers pay it down; reviews happen only after 3+ problems and at about 55%.
  - Rare rate is about 5% over a large sample; each pass through the shuffled bag shows all 13 regular animals.
  - Quest: N right in a row wins; any miss fails; no per-problem catches during a quest; the element reward prefers uncaught animals; Pick-a-Pet offers exactly the 13 regular + 5 rare animals; after a rare pick, rares are unavailable until the next day.
- **Parity check:** run the reference file and the port side by side in Playwright at 390×780. Screenshot the same states in each (practice, right answer, wrong answer, quest list, mid-quest, quest failed, element reward, Pick-a-Pet reward, backpack) and compare.
- ✅ **Checkpoint 1:** tests pass, the build is clean, no console errors, and the parity screenshots are shown side by side. List any differences.

### Phase 2 — Supabase: schema, RLS, auth
- Migrations in `supabase/migrations/`. Enable RLS on every table, with policies.
- Parent sign-up and sign-in, child profile create/edit/delete, PIN hashing, the "Who's playing?" screen, and the parent gate.
- Tests: RLS isolation between two parent accounts; the PIN is never stored in plain text; a child can't reach the dashboard without the parent gate.
- ✅ **Checkpoint 2:** show the migrations, policies and test results.

### Phase 3 — Connect the game to the backend
- Load each child's `game_state` and backpack when they're picked. Save changes as they happen.
- **Write queue:** attempts and catches go into a local queue (IndexedDB) and are sent in batches in the background. The game never waits on the network. The queue survives a page reload and retries when the device comes back online. Prevent duplicates with a client-generated UUID per row.
- Test: play 20 problems with the network off in Playwright, turn it back on, and confirm exactly 20 attempts arrive.
- ✅ **Checkpoint 3:** demonstrate offline play and sync, and two children on the same device keeping separate progress.

### Phase 4 — Parent dashboard
- Build the views above from `attempts`, `quest_runs` and `catches`. Do the heavy queries in SQL (views or RPCs), not by downloading every row.
- Seed script (dev only): a fake child with about 2,000 attempts so the dashboard can be checked with realistic data.
- 🔲 **Checkpoint 4:** screenshots of every dashboard view with the seed data, on phone and laptop widths. Hand-check a few numbers against raw rows.

### Phase 5 — Deploy
- Connect the repo to Vercel. Set the environment variables there. Add the Vercel URL to Supabase Auth's allowed redirect URLs.
- Smoke test on the live URL: sign up, create a child, play, win a quest, and check the dashboard.
- 🔲 **Checkpoint 5:** live URL plus smoke-test results. Note anything still on the to-do list.

## Out of scope (don't build unless asked)
- Accounts or logins for children
- Letting other families sign up publicly. Before opening it to other families, this needs a privacy review: it would be collecting data about other people's children under 13, which COPPA covers.
- Leaderboards, chat, or anything social
- Sound effects or new animals beyond the reference file (fine as later requests)
